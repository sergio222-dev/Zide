# Claude Code chat view (Alt+2) — phases 0 to 2
Objective: a full-screen Claude Code chat inside zide, driven by the user's own `claude` CLI over stream-json. This document covers phase 0 (land the spike), phase 1 (event model, transcript, status; no UI) and phase 2 (the full-screen chat view).
Branch: feat/claude-chat (from main, spike commits cherry-picked). Delivery: ask-on-risk, ~400 changed lines per slice. Runner: `cargo test -p zide-claude`.

## Specs
S1. Phase 0: the spike (`spike/claude-code-session`, crate `zide-claude`) lands on main's line, with a minimum CLI version pinned and the live tests ignored by default.
S2. Phase 1: `Event` carries what a chat needs: tool calls with id and input, tool results, thinking, usage, and the end of the process. Unknown fields and events are tolerated, never fatal.
S3. Phase 1: a pure `Transcript` (no UI, no process) built from events: user, assistant text, thinking, tool call with its result, permission, question, interruption and error blocks. Tool calls repeated by the stream are not duplicated.
S4. Phase 1: `Status` derived from the transcript, with the four states of the UI: "gris no activo, verde esperando input, naranja pensando", "azul cuando necesita al usuario". A pending permission or question wins over a running turn; the end of the turn clears anything still pending.
S5. Tests use fixtures captured from the real CLI (2.1.319), trimmed and without personal data.
S7. Phase 2: Alt+2 toggles a full-screen chat that replaces the editor area; it shows the history (Markdown for the assistant's text, a line per tool call, Allow/Deny for permissions), has a multi-line input (Enter sends, Shift+Enter adds a line, no vim), Esc interrupts a running turn and closes the view when idle. The session belongs to the Workspace, so a turn keeps running with the chat closed. Questions are denied on arrival with a plain-text reply until phase 4.
S6. No vim in the chat input box, the chat is a full-screen view on Alt+2 and the status bar shows the Claude icon with the colors above (later phases, out of scope here).

S8. Sessions: "habria que agregar a la interfaz la lista de sesiones, las sessiones se podran continuar como hace --resume." A list of the project's earlier sessions in the chat; picking one continues it (`--resume`).
S9. Slash menu: "una lista de comandos o skills como hace hoy claude code con la barra /".
S10. File mentions: "agregar archivos como con el @".
S11. Images: "agregar imagenes (ctrl+v)".
S12. Output formatting, after the above: "el formateo de la salida de la respuesta de claude usando gpui-kit en las tablas tal vez, folding de la salida, etc."
S14. Live chats panel: "un panel a un costado para mostrar las sessiones/agentes vivos que estan corriendo"; several chats at once, each with its own state (gray no process, green idle, orange working, blue needs the user). Closed stored sessions are not resumed until an input is sent: "si esta cerrada no se deberia retomar el proceso hasta que se envie un input".
S15. Status bar: "los estados de la status bar ahora pasan a las sesiones y el status bara ahora es gris si no hay agentes corriendo, naranja con al menos 1 agente pensando y verde en idle (ningun agente pensando y al menos uno esperando respuesta)".
S13. The status bar icon (phase 3) is postponed: "no vi el icono de claude, lo podemos dejar para mas adelante".
